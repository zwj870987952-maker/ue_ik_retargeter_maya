# A/B 缓存与 UE 实际动画输出验证

Maya 2024.2；UE 5.8.1-56057345。测试使用当前 `test_maya.ma` 中
`CC_Base_BoneRoot` → `mixamorig:Hips`，动作来自
`D:/动作库/CC/studio-mocap-shopping/shop_sales_walkintro_f.fbx`，范围 0–403、30 fps。

参考资产是 `/Game/测试/woman/RTG_AutoGenerated.RTG_AutoGenerated`。
UE 中已有的 `A_shop_sales_walkintro_f` 的导入源文件与本次 FBX 相同。
通过临时复制 RTG、执行 UE 的实际批量重定向，再以 `AnimPoseExtensions`
读取输出，获得 11 个采样帧的 Source 101 / Target 65 个骨骼变换。
临时 UE 资产已删除，没有保存原 RTG 或原动画。

资产实际启用 Pelvis Motion、FK Chains；Run IK Rig 和 Root Motion 关闭。
Source Retarget Pose 无旋转偏移，Target 有 31 个局部旋转偏移；
FloorConstraintWeight=0、AffectIKHorizontal=1、AffectIKVertical=0。
Pin Bones 的列表为空；本轮只比较骨骼姿态，不比较自定义动画曲线。

同帧全部目标骨骼的最大位置差为约 **0.0016 cm**，旋转差约 **0.0145°**。
这是 11 个采样帧的 UE / Maya 比较；完整 404 帧已在 Maya 烘焙。
该精度不代表所有骨架、所有动画及全部 UE Op 已覆盖。

数据和脚本：

- `export_ue_reference.py`：在 UE Python 中执行，导出准确参考姿势、RTG 参数及实际动画输出。
- `ue_profile.json`：供 Maya 的“应用 UE 导出的 RTG 配置”使用。
- `ue_reference.json`：UE 实际采样输出，包含 FBX 导入路径与临时资产清理结果。
- `compare_live_ue.py` / `maya_ue_comparison.json`：当前保留缓存与 UE 的逐骨骼比较。
- `validate_live_session.py`：缓存输入 / 输出一致性、往返拖帧、可选单次 PBIK、失败导入清理，以及删除后重新导入的回归验证。
- `deletion_verification.json`：两套系统确实删除后，原 B 独立动画与 UE 输出的比较。
- `restart_validation.json`：Maya 重启后恢复两个未知求解节点，全部 2403 条动画曲线节点保持不变，并重新核对 UE 输出。

## 当前数据流

1. 后台复制骨架并装配缓存，另存 `.rig.ma`（内含完整 manifest）和 `.rtg.json`，删除后台副本。生成不改变原骨架或动画，也不保存原场景。
2. 重定向导入独立 namespace 的 A/B 缓存。按稳定骨骼 ID 建立动画与求解器索引关系，避免复制后的 DAG 遍历顺序改变导致错接骨骼。
3. 将原 A 的输入动画逐帧复制到缓存 A。源 IK 默认关闭，保持与 UE 读取源动画的语义相同。
4. 固定 Reference Pose 和 Retarget Pose，按骨盆、FK、可选目标 PBIK 顺序求值。目标 PBIK 每次计算统一接收完整姿态及四个 Goal。
5. 通过无连接的接收骨架计算局部 TRS，在原 B 上创建独立曲线。删除缓存 namespace 不删除原 B 的曲线。
6. 测试阶段默认保留系统；编辑系统后可重新烘焙，或点击删除缓存系统保留 B 动画。

## 与 UE 源码对应的修正

- `IKRetargetProcessor.cpp:28`：参考姿势与局部 Retarget Pose 偏移按层级展开。FBX 骨轴基变换后应用局部四元数偏移，不将其当作世界偏移。
- `PelvisMotionOp.cpp:289`：按准确参考身高计算比例，支持分轴绝对位移混合、地面约束、局部 / 全局微调。缓存中的诊断性身高比例不覆盖运行时计算值。
- `PelvisMotionOp.cpp:385`、`RunIKRigOp.cpp:127`：Affect IK 只抵消骨盆微调产生的增量，保留动作本身的骨盆位移。
- `IKRetargetProcessor.cpp:675`：链插值使用 UE 的最短弧 FastLerp / Normalize。
- `RunIKRigOp.cpp:278`：只在 Op 启用时，把完整 FK 姿态传给 IK Rig，一次取回完整求解结果。

缓存文件属于本机生成物，位于被忽略的 `test/cache_workflow_assets/`。
当前原 Maya 场景未保存；动画、保留的系统和界面状态留在打开的会话中。

## 重启恢复

如果先打开场景、后加载求解插件，Maya 会将文件中的求解器保留为 `unknown`
节点，参数仍以原来的短属性名保存。启动界面时会加载求解插件，并将带
`ue58CacheRole` 标记的两个未知节点替换为正常求解节点，恢复参数与连接。
该步骤不重新导入动画、不删除动画曲线，也不重新打开或保存原场景。

2026-10-15 的恢复在 Maya 2024 新进程中完成。Source / Target 与各自原对象
的最大矩阵元素差分别约为 `8.7e-12` / `1.1e-8`；11 个采样帧与 UE 的差异
仍为上文记录的范围。

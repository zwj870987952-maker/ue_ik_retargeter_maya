# 膝盖朝向与直腿极向量

PelvisRoot 移除后的实机复验已通过：直接调整输入骨架的骨盆位置，并将四个手脚 Goal 切为世界空间固定目标，下蹲 10 cm / 20 cm 时四个膝盖仍向正确方向弯曲。测试恢复输入通道和原有动画连接，没有使用额外骨盆拖点。

当前 Maya 的 Mixamo 两侧膝盖使用 `+X / +90°` Preferred Angle 时，下蹲会向脚尖的反方向弯曲。根据实际骨骼坐标校准后使用 `-X / -90°`；CC4 保持原有 `-X / -90°`。这是当前 Maya 骨架的方向校准，不把 UE 模板中的轴符号当作所有导入骨架的固定规则。

## 直腿判定

设髋、膝、踝位置为 A、B、C，上下腿方向为 `u = normalize(B-A)`、`v = normalize(C-B)`，弯曲量为 `θ = acos(clamp(dot(u,v), -1, 1))`。θ=0° 表示伸直。膝盖偏离髋踝连线的向量为 `p = (B-A) - n*dot(B-A,n)`，其中 `n = normalize(C-A)`。

| 弯曲量 | 使用的极向量方向 |
|---|---|
| θ ≤ 3° | 稳定参考方向，忽略微小膝盖偏移的正负号 |
| 3° < θ < 8° | 参考方向与测量平面做 smoothstep 混合；先统一半球，避免跨直线时翻向 |
| θ ≥ 8° | 使用实际动画的弯曲平面，保留明确的弯曲动作 |

阈值使用角度，并记录膝盖偏离连线的高度占腿长的比例；不再以固定的 0.5 cm 判断各种尺寸的角色。3° / 8° 是本实现的稳定性阈值，可在 `core/pole_vector.py` 调整。

## 完全伸直时如何确定正确方向

完全共线的三个位置不能唯一确定“朝前”的极向量，必须有额外参考。建立参考时按以下顺序选取：显式 `pole_direction` → 有明显弯曲的绑定平面 → 脚踝到脚趾的方向在髋踝垂直平面的投影 → 已配置的有符号 Preferred Angle。

方向和髋踝轴保存在大腿骨的局部空间。求解时先随当前大腿旋转，再将参考轴平行运输到当前髋踝轴，最后投影到垂直平面。这样角色转向、抬腿和乱序跳帧都能得到一致结果；默认不依赖上一帧缓存。无解剖参考且没有明显弯曲时，会标记 `orientation_known=False`，不会把任选的垂直方向宣称为正确的解剖朝向。

## Preferred Angle 的符号校准

在实际 PBIK 骨骼坐标中进行一次 5° 的虚拟弯曲，计算预测的膝盖极向量。预测方向与参考方向的点积小于 -0.1 时反转 Preferred Angle 的符号，保留角度大小和关节轴锁定。该校准用于生成的 Source / Target 膝盖设置，也在创建实时求解器时使用其实际对齐后的参考姿态重新检查。设置 `auto_pole_direction=False` 可保留明确指定的骨骼角度。

实时 PBIK 通过校准后的 Preferred Angle 选择压缩腿的弯曲方向；重定向的 Two-Bone IK 与 Pole Vector Alignment 共用上述参考方向。两条极向量相反时，使用围绕髋踝轴的有符号 180° 旋转，避免任意旋转轴破坏脚部位置。

## 验证结果

9 项自动测试覆盖：完全直腿、正负微小扰动、不同尺寸、阈值过渡、角色转向、反向髋踝轴，以及原生 PBIK 在完全伸直输入上的下蹲。

Maya 2024 已验证两套角色各自下蹲 10 cm / 20 cm，四个膝盖均向正确参考方向弯曲；当前 Target 开启 Retarget Pose 对齐。解析 IK 的直腿用例、180° 极向量对齐、重新生成的骨骼参数和连续热重载也通过。热重载会同时重建本地求解缓存，避免旧 ctypes 类型造成求解停止。

测试保持 159 条动画曲线的键值、时间和连接，以及关节变换通道和原控制器姿态。场景未保存。数据见 [knee_pole_results.json](knee_pole_results.json)，测试入口见 [validate_knee_poles_maya.py](validate_knee_poles_maya.py) 和 [test_pole_vector.py](../test_pole_vector.py)。

# PelvisRoot 拖点的核对与取舍

已按确认完成移除：当前 Maya 的两个定位器已删除，生成、预偏移、自动同步和重置路径已清理；四个手脚 Goal、骨盆求解根与根行为保留。迁移前后位置变化为 0，159 条动画曲线及连接保持不变。移除记录见 [pelvis_root_removal.json](pelvis_root_removal.json)。以下保留移除前的核对与测量。

建议：为复现这两个 UE IK Rig，默认移除 Maya 的 PelvisRoot 拖点及对应的输入姿态预偏移。保留 Solver Root Bone、Retarget Root 和骨盆运动重定向。这三个概念不能一起删除。

## UE 实机与源码

本次重新读取 UE `5.8.1-56057345` 的 `IKRigController.get_all_goals()`，不是仅从 Retarget Chain 推断 Goal：

| 资产 | 完整 Goal 列表 | Solver Root / Retarget Root | Root Behavior |
|---|---|---|---|
| IK_AutoGeneratedSource | LeftFootIK、LeftHandIK、RightFootIK、RightHandIK | CC_Base_Hip | Free |
| IK_AutoGeneratedTarget | LeftFootIK、LeftHandIK、RightFootIK、RightHandIK | Hips | Free |

两个资产都没有 PelvisRoot Goal。数据见 [ue_pelvis_goal_check.json](ue_pelvis_goal_check.json)。这是当前资产的配置，不表示 UE 禁止用户手动建立骨盆 Goal。

`IKRigAutoFBIK.cpp` 从模板的肢体链创建 Goal，再单独将 pelvis 指定为 solver start bone，并设置 RootBehavior=Free。`IKRigFullBodyIK.cpp` 先输入当前骨骼姿态，再应用骨骼和手脚 Goal 参数求解；没有额外读取一个骨盆拖点后平移 / 旋转整个角色的步骤。

## Maya 中这个拖点实际做什么

当前原生 PBIK 仍只有四个 effector。PelvisRoot 并非第五个 PBIK Goal：它接入 `pelvisMatrix`，在 `core/ue58_pbik_node.py` 生成 PBIK 输入之前执行以下步骤：

1. 求控制器当前变换相对创建时变换的位移与旋转差。
2. 将骨盆以下整个输入分支平移 / 旋转。
3. 手脚 Goal 仍相对于未经该骨盆偏移的输入姿态计算。
4. 用新的输入姿态和四个 Goal 进行 PBIK 求解。

因此，它可以实现“手脚保持、主动压低骨盆”的下蹲测试，但属于 Maya 添加的输入姿态操纵功能。它没有独立 effector 的 StrengthAlpha、PinRotation、ChainDepth 或 PositionAlpha 权重。

## 测得的影响

测试临时替换节点的 pelvis 输入矩阵，没有拖动或修改用户控制器的动画。

| 条件 | Source | Target |
|---|---:|---:|
| 当前拖点回到创建姿态，与中性输入的最大骨骼位置差 | 0 cm | 0 cm |
| 拖点下移 10 cm、手脚 Goal 不动：骨盆输出位移 | 8.1448 cm | 8.3827 cm |
| 同上：最大骨骼位置变化 | 19.6268 cm | 19.0737 cm |
| RootBehavior 改为 PinToInput 后，拖点下移 10 cm：骨盆输出位移 | 10 cm | 10 cm |

中性时它没有改变当前结果。只要移动或旋转它，就会改变 PBIK 的输入姿态和骨盆输出；PinToInput 固定的是经过额外偏移的输入骨盆，而非原始动画骨盆。

还有一个代码层面的风险：`processor.retarget_frame()` 会将当前骨盆变换写回此控制器。骨盆位置已经包含根运动时，这条预偏移路径可能再次补偿骨盆位移。该风险来自调用路径检查，本次未将它作为已测得的烘焙重复位移错误报告。

数据见 [maya_pelvis_control_effects.json](maya_pelvis_control_effects.json)。测试后骨骼位置恢复误差为 0，动画键值和时间保持不变，场景未保存。

## 移除时应处理的范围

- `retarget_assets.py`：停止将 PelvisRoot 当作默认 Goal 组中的拖点生成。
- `fbik_scene.py` / `ue58_pbik_node.py`：移除它的矩阵接线和求解前的整分支预偏移；不再要求该定位器存在。
- `processor.py` / UI：移除骨盆拖点的自动同步和重置路径。
- 保留骨盆的 root index、Free / PinToInput / PrePull 设置、参考姿态和 Retarget Pelvis Motion；这些是 UE 对应的必要功能。
- 需要主动下蹲测试时，可通过输入骨架 / 动画控制器改变骨盆姿态，再让四个 Goal 约束末端。

移除已覆盖上述范围。旧节点的 `pelvisMatrix` 字段仅为读取旧场景而保留，已隐藏、断开拖点接线，且不再读取或参与求解。热重载会迁移旧节点并清理旧控制器。新的构建测试确认只生成四个定位器，见 [four_goal_builder_results.json](four_goal_builder_results.json)。

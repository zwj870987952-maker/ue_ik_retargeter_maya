# UE 5.8 FBIK 与 Maya test_maya 对照

> 本文记录修改前的诊断和旧求解器测量。后续已实现 UE 5.8 PBIK 核心与 Maya DG 接入；当前结果见 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)，实机数据见 [maya_pbik_results.json](maya_pbik_results.json)。下文的“当前版本”指诊断时的旧版本。

结论：当前版本能交互拖动四肢，但核心是“躯干启发式补偿 + 四次 Two-Bone IK”，尚未移植 UE 的 PBIK。要复现引擎效果，必须改变求解流程；只调整骨盆拉动比例、脊柱弯曲上限或界面参数不能达到一致结果。

本次使用实际运行的 UE **5.8.1-56057345** 和 Maya **2024.2**。UE 数据通过 5.8 的 `IKRigController → IKRigFBIKController` 读取；Maya 使用项目 `ue58_three_assets_v2` 中的实现。仓库最外层的旧版 `core/` 没有这个 FBIK 模块。

## 实机场景与资产

| 角色 | UE 资产 / Preview Mesh | Maya 骨架 | 骨骼链数量 UE / Maya |
|---|---|---|---|
| Source | `/Game/测试/woman/IK_AutoGeneratedSource`；`motion-dummy_male` | `CC_Base_BoneRoot`，CC4，101 joints | **31 / 21** |
| Target | `/Game/测试/woman/IK_AutoGeneratedTarget`；`X_Bot` | `mixamorig:Hips`，Mixamo，65 joints | **21 / 21** |

已在打开的 test_maya 中建立 `UE58_RetargetAssets_Grp`，包含两套 IK Rig、两套实时 FBIK、各四个手脚 Goal、各一个 PelvisRoot 控制器及 RTG 节点。装配时没有将 Target 改为自动对齐后的 Retarget Pose；这是为比较 IK Rig 的原始输入姿态。RTG JSON 中仍包含自动对齐定义。

测试结束恢复到第 0 帧和原始 Goal 姿态。最终检查曾发现原有曲线缺失，已从未改动的 test_maya 原文件恢复 **159 条曲线及全部原始连接**，关键帧时间和值与原文件的最大差约 **3.5e-18**。随后隔离动画连接重新完成探测，曲线数量 **159 → 159**，关键帧时间和值完全一致。没有保存或烘焙 test_maya，也没有修改或保存 UE 资产。接入期间原 Maya 2024 会话出现错误报告；本次装配是在重新打开 test_maya 后完成的，未恢复崩溃前未保存的编辑。

Maya 与 UE 的末端参考位置在本次 FBX 中满足 `UE(x,y,z) = Maya(x,z,y)`。Source 四个 Goal 的差异约为 1e-5 cm，Target 最大约 0.0044 cm。这个微小参考姿态差异远小于下文的求解误差。旋转转换需要用矩阵基变换处理，不能仅交换欧拉分量。

## UE 资产的实际设置

两个资产各有一个启用的 `IKRigFullBodyIKSolver`：

| 设置 | 两个 UE 资产 | 当前 Maya 实现 |
|---|---|---|
| RootBone | Source `CC_Base_Hip`；Target `Hips` | 骨盆识别正确 |
| RootBehavior | **Free** | JSON / 场景节点标为 **PinToInput**；内部仍按固定比例拉动骨盆 |
| Iterations / SubIterations | **20 / 10** | 没有对应的 PBIK 迭代 |
| MassMultiplier | **1** | 未参与求解 |
| AllowStretch | **false** | 解析四肢限制长度，没有 PBIK 的每轮去拉伸流程 |
| GlobalPullChainAlpha | **0** | 未实现 |
| MaxAngle / OverRelaxation | **30° / 1.3** | 未实现 |
| 四个 Goal 的 ChainDepth | **2** | 未实现子链约束求解 |
| StrengthAlpha / PullChainAlpha / PinRotation | **1 / 1 / 1** | 未实现这些独立参数；手部旋转处理与 PinRotation=1 不符 |
| Goal PositionAlpha / RotationAlpha | **1 / 1** | 有属性，但旋转权重被重复使用 |
| Goal PreviewMode | **Additive** | 当前是世界空间静态基准 Goal，未实现对应的动画输入偏移语义 |

`PullChainAlpha=1` 与 `GlobalPullChainAlpha=0` 同时存在是正常的：全局乘数让链的预拉动失效，但 **ChainDepth=2 / SubIterations=10 仍然有效**。

骨骼参数也有明确差异：

| 骨骼类别 | UE 实际值 | Maya 模板 |
|---|---|---|
| 骨盆旋转刚度 | 0.95 | 0.95，但求解器未消费该值 |
| 双侧锁骨 / Shoulder 旋转刚度 | **0.95** | **0.90**，并且未消费该值 |
| 双脚旋转刚度 | 0.85 | 0.85，但求解器未消费该值 |
| CC4 左右膝 | PreferredAngles **(-90,0,0)**；**Y/Z Locked** | `preferred_axis=-X`；**is_hinge=false** |
| CC4 左右肘 | PreferredAngles **(90,0,0)**；**Y/Z Locked** | `preferred_axis=+X`；**is_hinge=false** |
| Mixamo 左右膝 | PreferredAngles **(90,0,0)**；**Y/Z Locked** | `preferred_axis=+X`；**is_hinge=false** |
| Mixamo 左 / 右肘 | PreferredAngles **(0,90,0) / (0,-90,0)**；**X/Z Locked** | preferred axis 方向相同；**is_hinge=false** |
| 排除骨骼 | Source **CC_Base_Pelvis**；Target 无 | 有 Source 排除标记，但未建立 UE 的跳过排除骨骼的求解拓扑 |

UE 的骨骼刚度是约束更新中的实际权重，不是说明文字。`PBIKBody.cpp` 的位置、旋转修正分别使用 `1-PositionStiffness`、`1-RotationStiffness`，并结合质量和 OverRelaxation。

## Maya 实测

单位是 cm 和度。位置残差为求解后末端与其有效 Goal 的距离；旋转残差为末端与混合后的 Goal 旋转的角差。每个用例从同一基准姿态开始，结束后恢复关节和控制器。

| 用例 | CC4 Source | Mixamo Target | 含义 |
|---|---:|---:|---|
| 左手沿 Maya +Z 移动 20 cm，未移动右手的位置残差 | **17.03 cm** | **15.85 cm** | 未移动的手被跳过，随躯干 FK 漂移 |
| 同一用例，左手旋转残差，RotationAlpha=1 | **46.84°** | **38.15°** | 手旋转跟随前臂，没有遵守 UE 的 PinRotation=1 |
| 左手沿 +Z 移动 60 cm，左手位置残差 | **7.07 cm** | **9.91 cm** | 当前固定比例躯干补偿无法满足拉伸目标；尚未测得同输入的 UE 位置残差 |
| 同一用例，未移动右手位置残差 | **26.01 cm** | **23.10 cm** | 全身多目标耦合仍不成立 |
| 手 / 脚旋转 60°、RotationAlpha=0.5 | 约 **15°** 旋转残差 | **15°** 旋转残差 | 应先混合为 30°，当前再次乘 0.5，实际接近 15° |
| PositionAlpha=0、RotationAlpha=1，仅旋转左手 60° | **60°** 旋转残差 | **60°** 旋转残差 | 位置权重为零时直接跳过整个肢体，连独立旋转也失效 |
| 全部骨骼 rotation_stiffness 从 0 改到 1，左手 +Z 60 cm | 所有关节位置最大差 **0** | 所有关节位置最大差 **0** | 骨骼刚度参数没有进入算法 |
| 左脚抬高 20 cm | 位置、旋转残差接近 0 | 位置、旋转残差接近 0 | 基础解析腿部 IK 用例正常 |

静止用例误差接近零，说明主要问题发生在运动后的约束处理。单次探测的内部求解约 2–4 ms，不包含 Maya 完整视口刷新或交互延迟。

原文件中的 159 条曲线是静态参考姿态关键帧，不能用于验证动态动画兼容性。每帧输入姿态问题的判断来自下面的代码对照。

## 具体修改位置和顺序

### 1. 先修正 Goal 语义，建立可验证的基础

[fbik_solver.py:286](https://github.com/zwj870987952-maker/ue_ik_retargeter_maya/blob/fc8c0ce/ue58_three_assets_v2/ue_ik_retargeter_maya/core/fbik_solver.py#L286)

- 保留所有已连接的有效 Goal，包括没有被拖动的手。删除第 553 行“未移动的手直接 continue”的路径，否则双手双脚约束无法同时成立。
- Goal 的 PositionAlpha / RotationAlpha 只在目标混合阶段各使用一次。混合后的旋转交给独立的 PinRotation；默认 1 时，手和脚都输出有效 Goal 的绝对旋转。
- 将位置权重为零和旋转权重为零分别处理。第 543 行的整条肢体跳过会关闭仍有效的旋转。
- 将当前的固定基准 `base_world_*` 与逐帧 `input_world_*` 分开。Reference Pose 用于参考局部轴和限位；Input Pose 用于当前帧的骨长、输入局部变换、Goal 混合及输出。
- 明确支持 Additive 与 Absolute Goal。Additive 的零偏移应随当前动画输入；Absolute 才表示固定在世界 / 组件空间的目标。

UE 对应依据：`IKRigProcessor.cpp` 的输入姿态和 Goal 混合，以及 `IKRigFullBodyIK.cpp:95` 将已混合 Goal 交给核心求解器时把内部 PositionAlpha / RotationAlpha 固定为 1。`PBIKSolver.cpp:346` 在 PinRotation=1 时使用 `Effector.RotationFinal`。

### 2. 将实际资产参数贯穿数据、场景与求解器

[retarget_assets.py:226](https://github.com/zwj870987952-maker/ue_ik_retargeter_maya/blob/fc8c0ce/ue58_three_assets_v2/ue_ik_retargeter_maya/core/retarget_assets.py#L226)、[chains.py:195](https://github.com/zwj870987952-maker/ue_ik_retargeter_maya/blob/fc8c0ce/ue58_three_assets_v2/ue_ik_retargeter_maya/core/chains.py#L195)

- 使用上表中的 SolverSettings / GoalSettings / BoneSettings，补齐角度幅值、每轴锁定、PositionStiffness、PinRotation、StrengthAlpha 等字段。
- 自动装配配置使用 Free、20 / 10、GlobalPullChainAlpha=0、ChainDepth=2。Free / PinToInput / PrePull 要实现各自含义；PinToInput 必须锁住根的输入位移和旋转。
- 把锁骨刚度改成实际资产的 0.95，CC4 和 Mixamo 肘膝设置为实际的铰链锁轴。Preferred Angles 需要结合 Maya 关节局部参考轴转换，不能只使用世界前向向量作为替代。
- 当前场景节点的 `rotationStiffness` 等属性仅用于显示；需要增加求解时读取和缓存失效机制，以及相应参数变化的重新求解触发。
- 补齐 Source 的 10 条脚趾链。它们不是本次四个 FBIK Goal 失效的主因，但影响 RTG 链映射与完整资产一致性。

### 3. 用 PBIK 约束迭代替换躯干启发式补偿

[fbik_solver.py:361](https://github.com/zwj870987952-maker/ue_ik_retargeter_maya/blob/fc8c0ce/ue58_three_assets_v2/ue_ik_retargeter_maya/core/fbik_solver.py#L361)

目前的 90% / 96% taut threshold、0.22 / 0.45 骨盆拉动系数、18° 脊柱总弯曲和 16° 锁骨上限，都没有对应这两个 UE 资产的同名参数。需要替换为：

1. 建立关节拓扑、有效求解分支、排除骨骼后的父节点关系。
2. 建立骨骼对应的 rigid bodies、质量、body-local bone offsets。
3. 建立四个 Effector pin constraints 和相邻 body 的 joint constraints。
4. 每帧从输入姿态更新 bodies、局部 pin、骨长与设置。
5. 按子链压缩程度施加 Preferred Angles；GlobalPullChainAlpha=0 时跳过预拉链。
6. 先进行 **10 次子链求解**，锁住子链以外 bodies；再进行 **20 次全身求解**。
7. 在迭代中应用 position/rotation stiffness、锁轴、质量、MaxAngle、OverRelaxation，以及每轮 RemoveStretch 和末轮 FinalPass。
8. 按根到叶顺序重建输出骨骼。非求解骨骼保留当前帧的输入局部变换，并随求解后的父骨骼传播。

这些阶段直接对应本机 UE 的 `FPBIKSolver`。保留现有 TwoBoneIKSolver 可用于其他独立链模式；默认 FullBodyIK 路径应实现上述 PBIK 行为。

### 4. 最后改为稳定的 Maya DG 求解节点

[fbik_solver.py:625](https://github.com/zwj870987952-maker/ue_ik_retargeter_maya/blob/fc8c0ce/ue58_three_assets_v2/ue_ik_retargeter_maya/core/fbik_solver.py#L625)

当前同时使用 attribute callback 和 expression，求解函数直接用 `cmds.xform` 写关节；expression 只显式依赖 Goal 的 translate/rotate。这不够表达动画输入、世界矩阵、父组变换和所有设置的依赖关系。

另已实测：对连接原始动画的 Hips 调用一次世界旋转 `xform`，即使设置为查询得到的原旋转，也会改变现有动画曲线的值。这说明直接写原骨骼还存在修改原始关键帧的问题。本次装配 / 探测脚本已加入临时断开与恢复动画连接的保护；生产求解器应通过独立输出驱动或动画层处理这个问题。

建议建立 `MPxNode`：输入骨架 parent indices、Reference Pose、当前 Input Pose、Goal 矩阵、全部设置，输出求解后的局部矩阵。再用独立驱动层连接输出或烘焙动画。这样可以明确处理 scrubbing、父组移动、批处理和重开场景后的重建，并减少回调重入和重复求解。

若复现精度是首要目标，优先做 C++ 的 PBIK 数学核心和 Maya 节点适配，再沿用 Python 的资产和 UI 层。纯 Python 原型也能实现相同约束流程，但应先在内存 pose buffer 上验证，不直接把重写算法放入现有回调写关节的路径。

## 建议验收

先在两套相同参考骨架上固定输入，使用零偏移、单手 20 / 60 cm、双手相反方向、抬脚、骨盆下蹲、纯旋转、0 / 0.5 / 1 权重、0 / 1 刚度、锁轴等用例。保存 UE 和 Maya 的逐骨骼输出位置 / 四元数，在统一坐标系比较；再增加动态 Input Pose、时间跳转和父组变换。

其中手脚旋转、权重独立性、锁轴和参数生效可以先设置明确断言。竞争目标、无法到达目标和躯干姿态应以 UE 的输出为基准，不要求数学上不可达的目标位置误差为零。

本次已确认 **UE 实际参数、源码行为和 Maya 的可复现缺陷**，没有导出同输入的 UE 求解后逐骨骼数值，因此没有声称完成 UE / Maya 姿态数值一致性验证。

本目录保留参数快照、旧求解器测量和诊断脚本：`ue_asset_snapshot.json`、`maya_probe_results.json`、`export_ue_assets.py`、`assemble_maya.py`、`probe_maya.py`。这些历史脚本针对修改前的求解器；当前验收入口见 `IMPLEMENTATION_STATUS.md`。原始 Maya 场景、曲线备份和生成的场景资产留在本机，不随代码发布。

# RTG 重定向流程与动画预览审阅

2026-10-14；代码基线 `ac5a21c`；Maya 2024 当前 `test_maya.ma`；UE 5.8.1 的 `/Game/测试/woman/RTG_AutoGenerated`。

Maya 可以提供“加载 RTG 配置和源动画，播放或拖动时间轴，实时查看目标角色”的工作流。当前版本只有手动的当前帧重定向和烘焙入口，尚未完成等同 UE Retarget Editor 的连续、可撤销、不改动画的预览。此前通过的 PBIK / 膝盖测试覆盖 IK Rig 交互；本次检查动画重定向时发现独立的流程问题。

审阅仅新增本目录的脚本、快照和报告，没有修改生产代码。Maya 测试使用两个原角色的隔离骨架副本，副本和测试节点均已清理。原场景的 159 条动画曲线、键值、连接、骨骼通道和原求解器注册表保持不变；当前帧仍为 2，场景未保存。

**UE 资产的实际配置**

先查询活动 UE 编辑器，再读取已保存包的临时副本，以区分编辑态与磁盘状态。原资产当前为 dirty；以下开关和骨盆参数在两个快照中一致。临时包已删除，原 `.uasset` 字节未改变。

| Op | 实际启用 | 对当前结果的意义 |
|---|---|---|
| Pelvis Motion | 是 | 转移骨盆运动 |
| FK Chains | 是 | 21 条目标链的 FK 转移 |
| Run IK Rig | 否 | 当前预览不执行此 Op 的全身 IK |
| Root Motion | 否 | 当前预览不执行此根运动 Op |
| Remap Curves | 是 | 复制源动画曲线 |
| Pin Bones | 是 | 配置中的 BonesToPin 为空 |

该资产没有独立的 IK Chains / Align Pole Vector Op。Source 和 Target 都使用 Default Pose；Source 无旋转偏移，Target 保存了 31 个骨骼旋转偏移。骨盆 `FloorConstraintWeight=0`、`AffectIKVertical=0`、`AffectIKHorizontal=1`。Maya 场景生成的 RTG 则声明 IK Chains、Run IK Rig、Align Pole Vector 都启用，FloorConstraintWeight / AffectIKVertical 均为 1。这些配置不能直接当成同一套执行流程。

活动 UE 的 FK / Run IK Rig 设置引用一个临时目标 Rig；已保存包的相应可选引用为空，默认 Target IK Rig 仍为用户指定的 `IK_AutoGeneratedTarget`。本报告不把临时 Rig 当成可发布依赖，也没有替用户保存当前 UE 编辑态。

数据：[活动编辑态](ue_retarget_snapshot.json)、[已保存包](ue_saved_retarget_snapshot.json)；读取脚本：[inspect_ue_retargeter.py](inspect_ue_retargeter.py)、[inspect_ue_saved_copy.py](inspect_ue_saved_copy.py)。

**需要修复的流程问题**

1. **P1：动画重定向没有正确集成新 PBIK。** [processor.py](../../ue58_three_assets_v2/ue_ik_retargeter_maya/core/processor.py) 的 `retarget_frame()` 第 364 行仍调用 TwoBoneIKSolver，逐个处理四肢。UE 的 `RunIKRigOp.cpp:315` 则把完整 FK 输出交给 IK Rig，统一求解后再取回完整输出。隔离测试中，不装目标 DG 节点时，每帧 Two-Bone 求解 4 次、原生 PBIK 0 次；装上生产 PBIK 节点后，每次预览原生求解达 70 次。原因是逐骨骼世界变换写入不断触发仍然启用的 DG 节点，之后又同步四个 Additive Goal；`_is_solving` 不会关闭 DG 求解。动画路径还可能把已对齐的输出再次送入节点的参考姿态对齐。重复预览同一帧，骨盆相对内部目标位置的残差从 2.27 cm 变为 3.62 cm，最大旋转残差从 39.46° 变为 45.88°。这些数字是“内部指定姿态与实际 Maya 输出”的差异，**不是 UE / Maya 黄金姿态误差**。

2. **P1：当前帧预览会写动画，烘焙仍依赖活动求解节点。** [main_window.py](../../ue58_three_assets_v2/ue_ik_retargeter_maya/ui/main_window.py) 第 498 行的预览直接执行 `retarget_frame()`；后者经 [math_utils.py](../../ue58_three_assets_v2/ue_ik_retargeter_maya/core/math_utils.py) 第 65 行的 xform 写目标 TRS。当前 Maya 开着 Auto Key；在隔离目标上执行一次预览，原有两个 0 值关键帧变成三个键，新增值约 1.5734°。同时，给装着 PBIK 的副本烘焙当前帧后关闭节点，最大位置变化 38.58 cm、旋转变化 47.42°。当前烘焙把活动 offsetParentMatrix 的补偿结果写入通道，尚不能作为脱离节点后姿态一致的最终动画。

3. **P1：重复加载缓存会累积动画位移。** UI 每次预览都会在 `_ensure_processor()` 第 465 行重新应用缓存。[retarget_assets.py](../../ue58_three_assets_v2/ue_ik_retargeter_maya/core/retarget_assets.py) 第 962 行从当前目标根位置推断场景摆放偏移；Mixamo 的根就是动画中的 Hips。隔离测试保持源姿态和帧不变，连续三次加载相同缓存并预览，目标骨盆 X 从 14.878 cm 到 29.756 cm、44.635 cm；第一次到第三次的总位置差为 35.76 cm。显示摆放应来自稳定的角色父组 / 单独存储的摆放矩阵，参考姿态应在启动预览时固定。

4. **P2：RTG 配置尚未完整执行和还原。** loader 恢复了部分姿态和开关，但没有应用序列化的 `chain_mappings`。测试要求 LeftArm 映射到 RightArm、RotationAlpha=0.123、EnableFK=False；加载后仍为 LeftArm、1.0、True。IK Chains / Run IK Rig 的两个开关被合并成一个 enable_ik_pass；Pelvis / FK 的独立 Op 启用状态、顺序和完整参数没有对应的运行栈。场景中的 RTG Op / Chain 节点属性也主要是描述信息，没有像新 IK Rig 设置那样接入计算图。需要让同一份 RTG 数据实际驱动求解、编辑和导出。

5. **P2：缺少连续动画预览和动态验收。** UI 只有“预览当前帧”和烘焙，没有源到目标的时间 / 姿态依赖节点。当前场景未发现 RTG 预览回调，159 条原曲线仅在 0、1 帧有静态值，没有一条变化曲线。现有场景可验收控制点交互，无法据此认定行走、转身、下蹲或脚步接触已经复现 UE。本次副本测试有合成的抬臂、下蹲和水平移动，仍未取得同一真实动画在 UE 中的逐骨骼输出作为基准。

实机数据：[maya_retarget_review.json](maya_retarget_review.json)；复跑脚本：[probe_maya_retarget.py](probe_maya_retarget.py)。脚本使用当前场景的 CC4 / Mixamo 两套骨架复制品，始终在 finally 中清理测试对象并核对原动画。

**对应 UE 的 Maya 预览应如何工作**

RTG 入口使用本项目的 `.rtg.json` 和配套 IK Rig 配置、或 Maya 场景中的 RTG 节点；当前工具没有直接读取 Unreal `.uasset` 的入口。用户加载源角色动画后，可以播放、拖帧、改参数、停止预览，再选择单独烘焙。

计算时先固定 Source / Target Reference Pose 和 Retarget Pose，再读取当前帧源动画。按 RTG 的实际 Op 顺序与开关运行骨盆、FK、Goal 生成，以及启用时的 Run IK Rig；每个已启用的 Run IK Rig Op 把完整输入和全部 Goal 交给原生 PBIK。目标动画预览通过独立输出层或矩阵节点显示，不回写输入通道、不把最终骨骼位置回写到 Additive Goal 控制器。

预览、拖帧和烘焙使用同一套求解函数。烘焙先取得最终输出姿态，再在固定的基准 offsetParentMatrix 下写正确的局部 TRS；移除预览连接后结果应保持一致。重复预览同帧、往返拖帧、加载同配置都应给出稳定结果，Auto Key 开关不能改变用户动画。

实施顺序：先修正 RTG 数据还原和固定参考 / 摆放；再把动画重定向改成纯姿态输入输出并正确集成条件 PBIK；随后添加连续预览与独立烘焙；最后用同一条真实动画、相同骨架和相同 RTG 配置，比较 UE / Maya 多帧逐骨骼位置、旋转及脚接触。

UE 源码核对入口（本机 `E:/UE5/UE_5.8/Engine`）：`Plugins/Animation/IKRig/Source/IKRigEditor/Private/RetargetEditor/IKRetargetAnimInstanceProxy.cpp:58` 的连续预览求值；`Plugins/Animation/IKRig/Source/IKRig/Private/Retargeter/RetargetOps/RunIKRigOp.cpp:278` 的完整姿态求解；`IKChainsOp.cpp:288` 的 Goal 生成；`IKRigEditor/Private/RetargetEditor/IKRetargeterController.cpp:383` 的默认 Op 添加逻辑。
